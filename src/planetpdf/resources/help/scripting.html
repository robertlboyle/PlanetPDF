Scripts, Programs, and Plugins

Everything PlanetPDF does in its window can also be done without it: from a command prompt or script, by another program, or by a plugin that adds its own items to PlanetPDF's menus. This chapter explains what each is for and how to use it. It works the same on Windows, the Mac, and Linux.

Which one do I need?

  • The command line is for people and IT who want to repeat a task on many files, or run it on a schedule: compress every scan in a folder overnight, add Bates numbers to a set of exhibits, fill a form from data. You type planetpdf and a command in a command prompt, PowerShell, or a script.
  • The local API is for programmers: another program on your computer asks a running PlanetPDF to do the work.
  • Plugins are small programs someone wrote that add items to PlanetPDF's menus, such as "File Invoice" on the Tools menu.

Signing always asks you. Scripts, programs, and plugins may use every function, but whenever one wants to digitally sign a document with your Digital ID, PlanetPDF shows a window asking you first. A script can't answer it for you.

The command line

Where to run it

  • Windows: the installer adds PlanetPDF to the PATH (the task "Let command prompts and scripts run planetpdf", ticked by default), so planetpdf works in any new command prompt or PowerShell window. Without it, use the full path: & "C:\Program Files\PlanetPDF\PlanetPDF.com" help.
  • Mac: /Applications/PlanetPDF.app/Contents/MacOS/PlanetPDF help in Terminal.

Running planetpdf with a file name instead of a command simply opens the file in the PlanetPDF window, as before.

Getting help

Examples

planetpdf info report.pdf
Shows the pages, size, details, protection, signatures, and form fields.

planetpdf export report.pdf --format docx --out report.docx
Saves a Word copy.

planetpdf compress scan.pdf --quality small --out scan_small.pdf
Makes a smaller copy.

planetpdf redact report.pdf --preset ssn --find "John Q. Public" --overlay-text REDACTED --out report_redacted.pdf
Removes every Social Security number and the name for good, then checks the result.

planetpdf fill form.pdf --set "Name=Jane Doe" --set Agree=on --flatten --out filled.pdf
Fills in a form and makes the answers part of the page.

planetpdf sign contract.pdf --id <ID from signing-ids> --out contract_signed.pdf
Signs with a Digital ID from your certificate store; PlanetPDF asks you first.

In PowerShell, to compress every PDF in a folder:

Get-ChildItem *.pdf | ForEach-Object { planetpdf compress $_.FullName --out ($_.BaseName + "_small.pdf") }

How commands behave

  • Files: a command never writes over an existing file unless you add --overwrite. It writes over its own input file only when --out names that file.
  • Pages are typed as in the program: --pages "1-3, 7, 10-" (10 to the end).
  • Output: a readable summary, or the result as JSON with --json (for scripts). Progress ("Reading page 3 of 10") is shown separately (on stderr), so it never mixes with the result; --quiet hides it.
  • Exit codes tell a script how it went (%ERRORLEVEL% in a batch file, $LASTEXITCODE in PowerShell):
CodeMeaning
0Done.
1It failed; the message says why.
2The command was used wrongly (unknown command, missing or bad option).
3Signing wasn't approved.
4Done, but a check failed (redaction verification, compliance check).
130Stopped with Ctrl+C.

Passwords

For a protected file, or a Digital ID file's password:

  • --password - asks you to type it (it isn't shown as you type).
  • --password env:NAME reads it from the environment variable NAME.

Caution: a password typed straight on the command line (--password secret) can be seen by other programs on the computer. Use one of the two ways above.

Signing from the command line

planetpdf signing-ids lists the Digital IDs in Windows' certificate store (or the Mac Keychain) that can sign. Pass one with --id, or a Digital ID file with --pfx. Every time, PlanetPDF shows Allow Digital Signing? describing what will be signed; click Allow or Don't Allow. If it isn't allowed, the command ends with exit code 3.

Two more commands are for programs: planetpdf commands lists the commands, and planetpdf serve runs the local API without a PlanetPDF window until you press Ctrl+C.

The local API (for programmers)

Other programs on your computer can ask PlanetPDF to do work through its local API: JSON-RPC 2.0, one JSON message per line, over a named pipe (Windows) or a socket file (Mac, Linux). Only programs running as you on this computer can connect; it is never open to the network. Every command of the command line is an API method of the same name, with the same options, and long jobs send progress as they go.

  • A running PlanetPDF writes the connection's address to api.json in its local app data folder (Windows: %LOCALAPPDATA%\Planet Networks\PlanetPDF). Without a PlanetPDF window, planetpdf serve provides the API.
  • The first time a program connects, PlanetPDF asks you whether to Allow it, showing the program file it really is (from the computer, not the name the program gives itself). Click Allow only if you started or installed that program yourself. It then gets a key (token) that works only for that program file; if another program uses the key, you're asked again. It appears in Preferences ▸ Scripting & Plugins, where you can block it.
  • The first time a program wants to sign, you choose Allow Once, Always Allow This Program (until you click Stop Signing in Preferences), or Don't Allow.
  • Each program may make 10 requests a second and run 2 jobs at once.

Programmers will find a ready-made Python client (planetpdf_client.py, standard library only) and an example plugin in the sdk folder of PlanetPDF's resources, and the full description (methods, messages, error codes) in the developer guide, docs/SCRIPTING.md.

You can turn the API off for yourself: untick Let other programs and plugins use PlanetPDF in Preferences ▸ Scripting & Plugins (it takes effect the next time PlanetPDF starts).

Plugins

A plugin is a small program that adds commands to PlanetPDF's menus. When you choose one of its items, PlanetPDF starts the plugin as a separate program, which then uses PlanetPDF through the local API, for example to stamp and file the open invoice.

Adding a plugin

  1. Choose Help ▸ Open Profile Folder and open the plugins folder (make it if it isn't there). On Windows this is %APPDATA%\Planet Networks\PlanetPDF\plugins.
  2. Copy the plugin's folder into it. (IT can also make plugins available to everyone from folders listed in the environment variable PLANETPDF_PLUGINS.)
  3. Turn it on, as below.

Turning a plugin on

Nothing a plugin contains runs until you turn it on.

  1. Choose Edit ▸ Preferences… and click Scripting & Plugins.
  2. Under Plugins, find it. The Asks to column says what it wants to do through PlanetPDF:
    • read documents: details, text, form fields, searches, and checks;
    • write: make new documents and change documents;
    • sign documents with your Digital IDs (you are still asked before it signs).
  3. Tick it. Turn On Plugin? shows its publisher, what it asks for, and the menu items it adds. Click Yes only if you trust where it came from.
  4. Its items appear at the end of the menus it names (File, Edit, View, Tools, Window, or Help) in every window.

To turn it off, untick it.

Changed plugins turn off. PlanetPDF remembers exactly what the plugin's files were when you turned it on. If any of them change (an update, or tampering), it is off again until you turn it on again, so you see what it asks for each time it changes.

What a plugin prints goes to logs\plugins in the profile folder, and what it did through PlanetPDF is in the Activity Log….

Important: a plugin is a program running as you, like any program you start. Its permissions limit what it can do through PlanetPDF (asking for anything else is refused), not what it could do on its own. Turn on only plugins from people you trust.
