For IT: Shared Computers and Policies

This chapter is for the people who install and look after PlanetPDF for others: on office PCs, and on computers many people sign in to at once, such as terminal servers (Remote Desktop, Citrix). It covers installing without questions, deciding settings for everyone with a policy file, updates on computers where users can't install anything, and what PlanetPDF keeps where.

Installing for everyone

The Windows installer installs PlanetPDF once for everyone who uses the computer, and needs an administrator. To install with no windows and no questions, run it with these switches from a command prompt or your deployment tool:

PlanetPDF-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES

Setup leaves out the natural reading voices unless you ask for them: add /COMPONENTS="main,printer,voices" to download them during setup (436 MB from software.planet.net, checked against the checksum built into Setup), or install them afterwards from a copy you keep, with no internet needed: PlanetPDF-Voices-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES (download it from the PlanetPDF page on software.planet.net). /COMPONENTS="main" leaves out the PlanetPDF printer. /DIR="D:\Apps\PlanetPDF" chooses another folder. A silent install doesn't ask which app opens PDF files; set that with your default-apps policy.

Setup's exit code is 0 when everything asked for was installed, and 10 when PlanetPDF was installed but the PlanetPDF printer couldn't be added (for example, another program holds the printer's connection). The reason is in Setup's log (/LOG="C:\path\setup.log") and in printer\planetpdf-printer-setup.exe status.

Each person who signs in gets a PlanetPDF of their own: their own window, settings, signatures, and stamps. On a terminal server, people working at the same time never share one.

The natural voices go into PlanetPDF's folder, one copy for everyone. On a terminal server, install them that way if people will use Read Out Loud: over Remote Desktop PlanetPDF doesn't offer anyone a download of their own (354 MB each), only the page with the voices' installer. Each person reading aloud with the most natural voice (Kokoro) uses about 300 MB of memory while it reads; Piper's voices and the Windows voices use much less.

The install folder is protected

Setup lets only administrators and Windows itself change PlanetPDF's folder, wherever you put it; everyone else can read and run what is in it. This matters most on shared computers: the launcher there is run by everyone, and the PlanetPDF printer's service runs with system rights, so nobody but an administrator may be able to replace them.

  • In C:\Program Files a new folder starts out that way. Anywhere else (a data drive), a new folder usually lets every user write; Setup takes that away, for the folder and everything in it.
  • If Setup can't (a drive that doesn't keep Windows permissions), it says so at the end and doesn't add the PlanetPDF printer.
  • To check later, run planetpdf-printer-setup.exe status from the printer folder of the install folder. It lists the service, port, and printer, and whether only administrators can change the service's program and PlanetPDF's folder.
  • If you change the folder's permissions yourself, keep write access to administrators and SYSTEM only. The printer's service notes in its log (%ProgramData%\PlanetPDF\Spool\printer.log) when it finds itself somewhere others can write.
  • PlanetPDF's own small programs (the launchers and the printer's service and setup) load the Windows libraries they need only from Windows' System32 folder, never a file of the same name beside them.

A folder others could change. A folder that other users could write to at any time (installed by version 1.0.6 or older outside Program Files, or a folder that existed before) can't be trusted just by closing it: what someone put there while it was open, a program or a library in place of PlanetPDF's, would still be there. So:

  • Run PlanetPDF's installer on such a computer. It closes the folder before it runs anything in it (it stops the printer's service with its own copy of the setup program), removes what it didn't install from the folder, the printer folder, and the version it installs (programs, libraries, and links to other places), and then copies PlanetPDF's files.
  • PlanetPDF never asks for administrator rights to run its programs from such a folder. It checks every file and folder in it first. There it offers neither to install an update nor to bring the printer's service up to date, and says to run the installer instead, with the download page one click away.

Deciding settings for everyone: the policy file

By default each person chooses their own settings in Preferences. With a policy file you decide some of them once for everyone who uses the computer, and turn off features you don't want used there. The file is plain text named policy.json:

  • Windows: in PlanetPDF's install folder, beside PlanetPDF.exe (usually C:\Program Files\PlanetPDF\policy.json).
  • Mac: /Library/Application Support/PlanetPDF/policy.json
  • Linux: /etc/planetpdf/policy.json

An example that stops PlanetPDF from checking for updates by itself, checks signers' certificates online, and turns off plugins and web pages as PDFs:

{
  "settings": {"check_updates_on_start": false, "update_every_days": 0, "check_revocation": true},
  "off": ["plugins", "web_capture"]
}

PlanetPDF reads the file each time it starts. People see the settings you set in Preferences, grayed, with the note that their administrator set them; a feature you turned off says so when someone chooses it. What a person had chosen themselves is kept and comes back if you take the policy away.

Checking that your policy is in force

In a command prompt, type:

planetpdf policy

It shows the file PlanetPDF looks for, the settings and features it took from it, and anything it didn't take, with the reason: a name it doesn't know, or a value of the wrong kind (a number in quotes, for example). planetpdf policy --json gives the same for scripts. The exit code is 4 when something in the file wasn't taken, and 0 otherwise.

Only an administrator's file counts. A policy can also allow things, so PlanetPDF ignores a policy file that anyone but an administrator could have written or could change, and planetpdf policy says so. On Windows, the file and its folder must be writable only by administrators and SYSTEM, which Setup arranges for the install folder; create the file from an administrator command prompt or your deployment tool. On a Mac and Linux, the file and its folder must belong to root and not be writable by others.

Note: a policy is for managing a shared computer, not a lock on the person: someone who can run a copy of PlanetPDF of their own isn't held by it.

Updates where users can't install them

Installing an update needs an administrator. A person without administrator rights is told once that a new version is out; PlanetPDF doesn't download it for them. You have three ways to handle updates on such computers:

  • Install each new version with the full installer, as you installed the first. This also brings the newest PlanetPDF printer service, and is the way to move a shared computer up from version 1.0.6 or older: updates installed by those versions replaced only the program, not the printer's service or the program that starts PlanetPDF. (PlanetPDF says so when it starts on such an install; see "…is still from an older version".)
  • Let PlanetPDF update itself unattended. Run this as an administrator, or as a scheduled task under the SYSTEM account; it checks, downloads, and installs with no questions (exit code 0 = up to date or updated; 1 = it failed; 3 = not installed, because other users can change PlanetPDF's folder: run the installer instead, see The install folder is protected):
    & "C:\Program Files\PlanetPDF\PlanetPDF.exe" --install-updates
  • Leave it to administrators who use the computer: a person who can approve Windows' administrator prompt is offered updates as on their own PC.

A file named update.json beside PlanetPDF.exe changes how PlanetPDF checks, for everyone on the computer:

  • {"check": false}: people's PlanetPDF never checks for updates. The unattended update above still works. (A policy with "off": ["updates"] does the same.)
  • {"url": "https://files.example.com/planetpdf/"}: updates come from your own server, where you put the files from PlanetPDF's update site once you have approved a version. PlanetPDF installs only updates signed by Planet Networks, whatever server they come from.

Each version is installed in a folder of its own inside the install folder, so people still working in the old version aren't disturbed; old versions are removed once nobody uses them.

Environment variables

Set these for the whole computer (system variables) or for a person. A setting the policy file decides wins over a variable: a person's own PLANETPDF_PRINT_FOLDER doesn't change where printouts go when the policy sets print_folder, and PLANETPDF_UPDATE_URL doesn't make PlanetPDF check for updates when the policy turns updates off (IT's own --install-updates still uses it). planetpdf signatures follows the policy's check_revocation as the window does.

VariableWhat it does
PLANETPDF_PROFILE_DIRPuts each person's profile folder (settings, signatures, stamps) somewhere else, for example on a home drive: H:\PlanetPDF.
PLANETPDF_PRINT_FOLDER, PLANETPDF_PRINT_NAMEThe folder and name for printouts from the PlanetPDF printer when the person hasn't chosen their own (see Printing).
PLANETPDF_PLUGINSFolders with plugins offered to everyone (each person still turns a plugin on themselves).
PLANETPDF_UPDATE_URLThe address updates come from; set but empty, PlanetPDF doesn't check.

What people on a shared computer can't do to each other

  • Reach another person's PlanetPDF. A running PlanetPDF listens for its own later starts (and, when turned on, for programs using the local API) under a name made at random each time it starts, written only in that person's own folder, and each side proves it read that file before anything is said. Nobody else's program can stand in for it.
  • Receive another person's printout. The PlanetPDF printer hands each printout to the person Windows says printed it, in their own session; when that can't be told for sure, the printout is held for an administrator instead of being given to anyone.
  • Replace the program. Only administrators can change the install folder.

The names of documents waiting at the PlanetPDF printer can be seen in its queue by everyone on the computer, as with any shared Windows printer. If that matters, restrict the printer's permissions (Printer properties ▸ Security) so people manage only their own documents.

Checking an installation

  • The program: the self-test checks that every part is there and works.
  • The PlanetPDF printer: planetpdf-printer-setup.exe status in the install folder's printer folder.
  • Your policy: planetpdf policy.
